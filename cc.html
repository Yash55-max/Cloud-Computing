Introduction to Cloud Computing Fundamentals

IaaS · PaaS · SaaS · Deployment Models · Providers

What is Cloud Computing?

Cloud computing is the delivery of computing services — servers, storage, databases, networking, software, analytics, and intelligence — over the internet ("the cloud") to offer faster innovation, flexible resources, and economies of scale.

You pay only for the resources you use, helping lower operating costs, run infrastructure more efficiently, and scale as business needs change.

Defining a Cloud

NIST defines cloud computing by 5 essential characteristics:

On-demand self-service Broad network access Resource pooling Rapid elasticity Measured service
Cloud Computing Reference Model (Service Layers)

IaaS — Infrastructure as a Service

Provides virtualized computing resources over the internet. You manage OS, middleware, runtime, data, and applications. The provider manages hypervisors, servers, storage, networking.

Real-world Example
AWS EC2: Spin up a Linux VM in seconds. You choose CPU, RAM, storage. Pay per hour. Netflix uses EC2 to run its streaming backend.

PaaS — Platform as a Service

Provides a managed environment to develop, test, deliver, and manage applications. No OS or infrastructure management. Focus entirely on code.

Real-world Example
Google App Engine: Deploy a Python/Java/Go app — no server config. Scales automatically. App Engine handles load balancing, patch management, monitoring.

SaaS — Software as a Service

Complete applications delivered via browser. No installation, no maintenance. The provider manages everything from the datacenter up to the application.

Real-world Example
Gmail, Microsoft 365, Salesforce CRM, Zoom. You just log in and use it. Updates happen automatically with zero user effort.

Utility Computing

The packaging of computing resources (compute, storage, services) as a metered service, similar to traditional public utilities like electricity or water. Pay only for what you consume.

This model enables OpEx over CapEx — no upfront hardware investment, predictable monthly bills based on actual usage.

UNIT · II

Cloud Enabling Technologies

Parallel Computing · Distributed Systems · SOA · Web Services · RPC

Ubiquitous Internet & Why It Enables Cloud

Cloud computing fundamentally depends on pervasive, high-speed internet connectivity. The proliferation of broadband, mobile networks (4G/5G), and Wi-Fi means any device can access cloud resources anywhere. Without ubiquitous internet, the "thin client" model of cloud breaks down — you'd need local compute for everything.

Parallel Computing

Executing multiple computations simultaneously. Cloud datacenters run massively parallel workloads. Key elements:

Task parallelism Data parallelism Pipeline parallelism Synchronization
Example
Rendering a 4K video: each frame processed simultaneously across hundreds of CPU cores in parallel — minutes instead of hours.

Distributed Computing

Multiple computers working together over a network, appearing to users as a single coherent system. Cloud platforms are distributed systems at planetary scale.

Key challenges: consistency, availability, partition tolerance (CAP theorem).

Example
Google Search: a single query touches thousands of servers across multiple datacenters in milliseconds.

Remote Procedure Calls (RPC)

A protocol allowing a program to execute a procedure on a remote server as if it were local. The calling code has no awareness of the network underneath.

// Client calls remote function — looks local result = remote_server.calculateTax(income, year) // Under the hood: serialization → network → deserialization → execute → return

Modern implementations: gRPC (Google, uses Protocol Buffers), JSON-RPC, XML-RPC.

Service-Oriented Architecture (SOA)

An architectural style where software is structured as a collection of loosely coupled, interoperable services that communicate over a network. Each service encapsulates a business capability.

SOA principles: loose coupling, reusability, discoverability, interoperability. SOA is the philosophical backbone of modern cloud APIs and microservices.

Example
An e-commerce platform: separate services for inventory, payments, shipping, notifications — each communicating via defined contracts.

Web Services

Standardized means for machines to communicate over a network. Two main flavors:

SOAP (XML-based, strict) REST (HTTP, flexible) GraphQL (query-based)

REST APIs are the dominant interface for cloud services today. AWS, Azure, and GCP all expose management APIs over REST/HTTPS.

Inter-Process Communication (IPC)

Mechanisms for processes to exchange data and coordinate actions. In distributed cloud environments, IPC happens across machine boundaries.

Message Queues (SQS) Shared Memory Sockets / TCP Pipes Pub/Sub (Kafka)

Virtualization and Containers

Hypervisors · XEN · VMware · Docker · Kubernetes · EC2 · ECS
Virtualization Architecture: Type 1 vs Type 2 Hypervisor

XEN Hypervisor

An open-source Type 1 hypervisor. Uses paravirtualization — guest OSes are modified to be "aware" they're virtualized, calling the hypervisor directly instead of hardware. Results in near-native performance.

AWS originally built EC2 on Xen before migrating to their custom Nitro hypervisor. Still widely used in many cloud providers.

VMware vSphere / ESXi

Enterprise-grade Type 1 hypervisor and virtualization platform. Dominant in private cloud and on-premises datacenters.

Key components: ESXi (hypervisor), vCenter (management), vMotion (live VM migration), vSAN (distributed storage).

Use Case
A bank runs its core banking system on VMware private cloud — full hardware control, security isolation, compliance.
VMs vs Containers — Architecture Comparison

Docker

The dominant container platform. Packages an application and its dependencies into a container image — a portable, reproducible unit that runs identically anywhere Docker is installed.

# Dockerfile — defines the image FROM python:3.11-slim WORKDIR /app COPY . . RUN pip install -r requirements.txt CMD ["python", "app.py"] # Build and run docker build -t myapp . docker run -p 8080:8080 myapp

LXC — Linux Containers

The precursor to Docker. Provides OS-level virtualization by allowing multiple isolated Linux systems on a single host. Uses Linux kernel features: cgroups (resource limiting) and namespaces (isolation).

Docker originally used LXC as its execution engine before building its own libcontainer runtime. LXC is still used for full-OS container scenarios.

Kubernetes (K8s)

Container orchestration platform. Automates deployment, scaling, and management of containerized applications across a cluster of machines.

Pod scheduling Auto-scaling (HPA) Self-healing Load balancing Rolling updates Service discovery
Use Case
Spotify runs thousands of microservices on Kubernetes — auto-scaling during peak hours, self-healing on failures.

Amazon EC2 (IaaS)

Elastic Compute Cloud — AWS's VM offering. Choose from 500+ instance types. Supports Linux/Windows. Pay per second. Used for anything needing full OS control: databases, custom servers, ML training.

Amazon ECS (Container Service)

Elastic Container Service — AWS's managed container platform. Run Docker containers without managing a Kubernetes cluster. Integrates natively with IAM, ALB, CloudWatch. Fargate mode = serverless containers (no EC2 management at all).

UNIT · IV

Cloud Computing Challenges

Economics · Interoperability · Security · Federated Clouds · Fault Tolerance

Economics of the Cloud

Cloud shifts IT from CapEx (buying hardware) to OpEx (paying for usage). Key economic concepts:

Economies of scale: AWS buys hardware at volumes that reduce per-unit cost by 40–60% vs. enterprise buyers. These savings are partially passed to customers.

TCO vs. sticker price: Cloud appears expensive until you account for datacenter costs, cooling, power, staff, and hardware refresh cycles.

Cloud Interoperability & Standards

The ability to move workloads between cloud providers without lock-in. A significant unresolved challenge.

OVF (Open Virtualization Format) TOSCA (topology standard) CDMI (Cloud Data Mgmt) Kubernetes (portability)

Reality: Proprietary managed services (AWS RDS, Azure Cosmos DB) create deep lock-in. True portability requires discipline and often sacrificing convenience.

Scalability & Fault Tolerance

Horizontal scaling: Add more machines. Vertical scaling: Bigger machines. Cloud excels at horizontal.

Fault tolerance patterns:

Replication Circuit breakers Retry with backoff Multi-AZ deployment Health checks
Example
AWS designs every service assuming individual components will fail. S3 achieves 99.999999999% (11 nines) durability through automatic replication.

Federated Clouds

A model where multiple cloud providers collaborate to offer seamless resource sharing across their infrastructures. Users experience a unified pool of resources that spans provider boundaries.

Enables: disaster recovery across providers, avoiding single-vendor risk, geographic coverage gaps filled by federation partners.

Challenge: Identity federation, billing reconciliation, and consistent APIs across providers are unsolved at scale.

Energy Efficiency in Clouds

Hyperscale datacenters consume enormous power. Key metrics and approaches:

PUE (Power Usage Effectiveness): Total facility power ÷ IT equipment power. Lower is better. Google achieves ~1.10 vs. industry average ~1.58.

Liquid cooling Renewable energy PPAs Server consolidation via VMs Custom silicon (AWS Graviton)
Cloud Shared Responsibility Model (AWS-style)

Cloud Security Architecture

Defense-in-depth approach: security controls at every layer, assuming breach at any single layer. Key components:

Identity & Access (IAM/RBAC) Network security groups Encryption at rest & in transit SIEM / logging (CloudTrail) WAF (Web App Firewall) Zero Trust architecture Secrets management (Vault) Vulnerability scanning
Security in Deployment Models
Public cloud: Provider handles physical security, customer handles IAM and data encryption. Risk: misconfigured S3 buckets exposed publicly — a common breach vector. Private cloud: Organization handles full stack security — more control but higher operational burden. Hybrid: Security policies must span both environments consistently, requiring unified identity and logging.

Advanced Concepts in Cloud Computing

Serverless / FaaS Architecture (AWS Lambda Example)

Serverless Computing

A cloud execution model where the provider dynamically manages infrastructure allocation. Developers write functions, not servers. Key properties:

Event-driven Scales to zero No idle cost Stateless by default Cold start latency

AWS Lambda: Runs Node.js, Python, Java, Go, etc. Max 15 minutes per invocation. 1M free requests/month.

OpenFaaS: Open-source FaaS platform you can self-host on Kubernetes. Vendor-neutral alternative to Lambda.

Internet of Things (IoT) & Cloud

IoT devices generate continuous streams of sensor data that cloud platforms ingest, store, and analyze at scale.

Cloud-centric IoT layers:

Perception (sensors) Network (connectivity) Processing (cloud/edge) Application layer
Example
Smart factory: 10,000 sensors → AWS IoT Core → Kinesis Data Streams → Lambda → real-time anomaly detection → alert.

DevOps & Infrastructure as Code (IaC)

DevOps merges development and operations, emphasizing automation, continuous delivery, and shared ownership of systems. Cloud accelerates DevOps by making infrastructure programmable.

IaC means defining cloud infrastructure in code files — versioned, reviewed, and deployed like software.

# Terraform (IaC) — provision an AWS EC2 instance resource "aws_instance" "web" { ami = "ami-0c55b159cbfafe1f0" instance_type = "t3.micro" tags = { Name = "WebServer" } }
Terraform AWS CloudFormation Pulumi Ansible Helm (K8s)

Quantum Cloud Computing

Quantum computers use qubits and superposition to solve problems intractable for classical computers. Cloud provides access to quantum hardware via APIs — no need to own the cryogenic hardware.

AWS Braket IBM Quantum (cloud) Azure Quantum Google Quantum AI

Current state (2024): NISQ era — noisy, ~1000 qubits. Useful for optimization, cryptography research, drug discovery simulation. Fault-tolerant quantum is 5–15 years away.

Example
Running Shor's algorithm on IBM Quantum cloud to factor small numbers — demonstrating quantum advantage over classical approaches.

OpenFaaS — Open-Source Serverless

Run your own FaaS platform on any Kubernetes or Docker Swarm cluster. Functions packaged as Docker containers — any language, any binary.

# Deploy a function faas-cli new --lang python3 myfunction faas-cli build -f myfunction.yml faas-cli deploy -f myfunction.yml

Key advantage over AWS Lambda: no vendor lock-in, runs on-premises or any cloud, predictable costs for high-volume workloads.

Edge Computing

Processing data near where it's generated — in the device or a nearby server — rather than sending it to a central cloud datacenter.

Why it matters: Autonomous vehicles can't wait 100ms for cloud responses. Industrial robots need sub-millisecond control loops. Video analytics at scale would saturate network links.
